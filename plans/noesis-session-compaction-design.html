Design workshop · open

Durable session compaction

Compaction should reduce future model context without deleting, rewriting, or hiding the real conversation.

What exists now

Complete durable transcript

SQLite owns messages, tool calls, code runs, and their chronology. Resume rebuilds this full view.

Bounded turn context

Each turn creates a fresh Pi harness and admits only a recent bounded set of complete conversation turns.

A misleading command

/compact exists, but the production runtime has no durable compaction state.

Smallest coherent model

Append immutable context checkpoints and keep one active-checkpoint binding per session. A checkpoint preserves the useful meaning of older covered work so new work can fit; it does not promise full-fidelity replay inside model context. Its summary and retained raw tail remain subject to the existing hard per-fragment and total context bounds.

  • Raw transcript rows remain untouched and searchable.
  • Each checkpoint has its own identity and digest, a model-written summary, exact covered message or turn references and digests, sensitivity, model configuration, usage, and creation time.
  • A future turn freezes the exact checkpoint ID, digest, summary material, and recent raw-tail references into its FrozenTurnPlan.
  • Repeated compaction writes a new checkpoint from the prior checkpoint plus new eligible work. It never edits the earlier row.
  • After summary generation, checkpoint insertion and compare-and-swap of the active binding happen in one SQLite transaction. A failed or stale write changes neither.
  • Old frozen plans continue to cite the exact immutable checkpoint and raw context they used.

Questions to settle together

  1. Should the first version be manual only, automatic only near context pressure, or both?
  2. Where may a cutoff fall around steering, partial turns, and tool calls?
  3. Should private and secret content require a provider-specific replay grant before summarization?
  4. How much recent raw context must always survive beside the summary?
  5. What should the TUI show: checkpoint age, coverage, token reduction, and an inspect action?
  6. Should an overflowed turn compact and retry automatically, or ask the user to rerun?

Acceptance boundary

  • Resume still renders the complete original transcript.
  • Search still cites original authoritative rows.
  • Only future model context changes.
  • The checkpoint and retained raw tail always fit the same hard context limits as an uncompacted turn plan.
  • Every checkpoint can be inspected. Replacement changes only the active binding and never edits an earlier checkpoint.
  • No summary can widen permissions or instruction priority.
