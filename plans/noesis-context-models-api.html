Context and models in codemode

Give generated programs a complete session document and one way to ask a model about selected parts of it, without enlarging every foreground prompt or creating a second execution system.

Historical note: the lazy context design remains current, but the shipped models.query surface was superseded by the single composable agents.run API. Current behavior is specified in docs/agent-intelligence-and-experience.md.

Decision

Codemode receives two globals: a lazy immutable context view and models.query(prompt, context?). The latter is an ergonomic alias for an ordinary tool in the frozen Tool Catalog and Broker. 

const recent = context.slice(-20000);
const answer = await models.query(
  "List unresolved decisions and cite the supporting lines.",
  recent
);
return answer;

Why this shape

A bounded foreground prompt is good for conversation but a poor programmable data boundary. Codemode should be able to inspect a long session, partition it, run local transformations, delegate only the useful pieces, and combine the results. Passing the whole transcript into every model step would spend context before the program knows what matters.

The smallest useful API is therefore a document plus one model call. Search, map-reduce, batching, model selection, and summarization helpers can be written in ordinary JavaScript if real use proves they recur.

API contract

Surface Contract Important property
context.length JavaScript character length of the frozen document. Does not read the artifact.
context.slice(start?, end?) Returns another immutable view with ordinary slice indexes. Composes without copying text.
await context.text() Reads the selected range as text. Verifies digest and lengths before use.
models.query(prompt, context?) Accepts text, a context view, or an array of either. Isolated, tool-free, cancellable, and route-pinned.

The frozen document

Every admitted turn pins an immutable JSONL artifact representing the complete session before the current request. It contains visible user and assistant messages plus recorded tool calls, code executions, nested model calls, and workflow runs. It excludes the system prompt, current request, credentials, and internal background jobs.

The artifact reference, format, byte length, character length, and digest live in the frozen turn plan. The child receives only the verified path and identity. A resumed workflow restores the document pinned when that workflow run started; it does not silently switch to a newer session snapshot.

One invocation path

codemode JavaScript
  └─ models.query(prompt, ContextView)
       └─ SDK invoke envelope
            └─ frozen Tool Broker: models.query
                 ├─ validate handle against active execution
                 ├─ expand the selected immutable range
                 ├─ reserve network effect under current authority
                 ├─ run tool-free model on frozen route
                 └─ record request, output, usage, latency, and lineage

The child has no provider client. It cannot choose a hidden model, bypass permissions, or create an unrecorded nested call. Scripts, workflow phases, and ad hoc codemode all use the same globals and the same Broker definition.

Durable authority

Datum Authority
Session timeline facts Existing SQLite operational rows and message records.
Frozen context bytes Ordinary artifact file with SQLite metadata.
Turn context identity Immutable FrozenTurnPlan reference.
Workflow context identity Immutable columns on the workflow run.
Nested query status and lineage model_calls operational rows.
Exact nested request and output Artifact files referenced by the model call.

Alternatives not chosen

  • Injecting the full transcript into the foreground prompt couples analytical reach to conversational context cost.
  • Giving codemode a provider SDK creates a second route, permission, cancellation, and telemetry path.
  • Adding search, queryMany, or mapReduce now guesses at abstractions JavaScript can already express.
  • Letting resumed workflows see the newest session context makes a durable run depend on bytes it never started with.

Acceptance

  • The document contains prior visible and operational activity but not the current request.
  • Context views remain lazy, immutable, composable, and digest-verified.
  • A nested call expands only a handle from its active execution.
  • The nested model has no tools and uses the frozen foreground route.
  • Cancellation settles the model call and parent execution truthfully.
  • Request, output, usage, latency, and parent lineage survive restart.
  • Workflow resume uses the original context document and fails closed if it is unavailable.
