# Noesis four-week dogfood protocol

This protocol tests the product thesis: later related work should be better because earlier work happened. It is directional evidence from one primary user, not a validation study.

## Before starting

- Choose a start date and an end date exactly four weeks later.
- Use Noesis with the Pi runtime as the primary interface for real builder, philosopher, learner, and researcher work when practical.
- Create the friction log outside the Noesis workspace and repository. Noesis must not be able to edit, rank, or suppress it.
- Record the external log location privately; do not put sensitive work content in this protocol.

## External friction log

Record an entry when it happens, not at the end of the day:

| Field | Meaning |
| --- | --- |
| Timestamp | When the event occurred |
| Work scope | The narrow project or activity |
| Intended posture | Work with me or do for me |
| What happened | Observable behavior, without interpretation where possible |
| Friction or advantage | What became harder or easier |
| Prior work expected to help | The earlier session, correction, artifact, or adaptation |
| Did it help? | Yes, no, mixed, or not applicable |
| Correction signature | Stable short label for recurring corrections |
| Severity | Minor, meaningful, or workflow-breaking |
| Evidence pointer | Session/turn ID or external artifact reference, without copying secrets |

Log advantages as well as failures. Otherwise the protocol measures only irritation.

## Weekly readout

At the end of each week, report:

- number of real work sessions and eligible replay turns;
- replay coverage and exclusion reasons;
- recurring friction signatures and relevant exposure counts;
- examples where prior work clearly helped, clearly did not help, or leaked into unrelated work;
- context tax, paired win rate, scope leakage, and correction recurrence from the read model;
- work avoided because Noesis was not yet useful enough; and
- any protocol deviation.

Do not change product thresholds or broaden learning scope from a single striking example. Capture the observation and let recurrence decide whether it is a pattern.

## Four-week readout

Publish:

1. the recurring frictions, ordered by workflow impact;
2. evidence coverage, exclusions, scopes, model cohorts, and window;
3. the four provisional compounding metrics with their numerators and denominators;
4. three representative successful transfers and three failures or null results;
5. whether correction recurrence fell after activation for any signature;
6. whether unrelated-scope injection remained acceptably rare;
7. which product choices now have enough directional evidence to revisit; and
8. which questions still require contact with more users or a longer window.

The readout gates evidence-dependent posture heuristics, scope and threshold choices, metric interpretation, and product-success claims. It does not block correctness work or the single-authority cutover. A null or negative result is valid and must not be optimized away.
