Design workshop · open

The changes Noesis has made to itself

The user should be able to browse what changed, why it changed, where it applies, whether it helped, and how to reverse it.

Current surface

The existing /learning command shows session activity and the current project strategy as flat text. The durable system already contains much more: evidence, experiments, authored revisions, preflight, activation, feedback, outcomes, and reversals.

Smallest coherent product

Build an inspect-only Changes browser as a TUI overlay. Its default shows changes currently applicable in the active project, plus pending or evaluating changes that originated here before their applicability is settled. Origin remains visible but secondary to where a change can affect work.

List

Chronology, short title, applicability, current state, kind, latest outcome, and origin.

Detail

Observation, intended future use, applicability, origin, evidence, exact revision, evaluation, activation, feedback, and current status.

Raw view

Exact job IDs and stored records remain reachable for debugging without dominating the normal view.

Information architecture questions

  1. Which secondary filters should expose changes from this project that no longer apply here, or all personal changes regardless of origin?
  2. Should project strategies and durable capability revisions share one list but different detail templates?
  3. Do we show only material changes, while keeping no_change and routine jobs under diagnostics?
  4. After the inspect-only version, which protected action should ship first: unapply a project strategy, contest a lesson, or revert a durable revision?
  5. Should /learning open this browser or remain a terse textual summary?
  6. How should the TUI explain a change whose evaluation is still running without pinning transient status into the transcript?

Read-model boundary

The application composes one read model across authoritative adjustments, experiments, revisions, evaluation, activation, and feedback. It derives origin project through exact links to the source adjustment or source turn's frozen ProjectRef. Applicability remains a separate field from experiment or capability scope. The read model creates no second durable Change authority. The TUI renders it and owns no durable state. Missing links remain visible as incomplete data rather than being guessed from activity history.
